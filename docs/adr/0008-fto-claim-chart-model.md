# ADR 0008: FTO 比对模型——权利要求树、技术特征与逐项比对

- Status: Accepted（产品负责人于 2026-10-04 要求开始；本文范围为纯领域模型，不含 API、数据库与界面）
- Date: 2026-10-04

## Context

FTO 的核心问题是：己方产品是否落入他人有效权利要求的保护范围。比对以权利要求为单位，逐一检查
其每一个技术特征是否在产品中出现（ADR 0004：方向与可专利性比对相反）。现有 `comparison` 模块是
可专利性方向（已冻结），因此新建 `modules/fto`。

## 实测输入（2026-10-04）

- **美国权利要求**：ODP 每件授权记录的 `grantDocumentMetaData.fileLocationURI` 指向该专利的授权全文 XML
  （`PTGRXML`，USPTO API，同一密钥）。样本 60 件中 60 件有该地址，覆盖 2007–2026 年授权。XML 中：
  - 每项权利要求为 `<claim num="…">`；
  - 从属关系由专利局标注：`<claim-ref idref="CLM-00001">`；
  - 子句由嵌套 `<claim-text>` 标注（例：12630442 号权利要求 1 含 8 个子句：步骤 (1)–(7) 与一个 wherein 子句）。
- **欧洲权利要求**：EPO OPS `claims` 端点返回德、英、法三种语言，每种语言是一组平铺的段落
  （例：EP-1819002-B1 每种语言 18 段）。权利要求编号写在文本里（“1. A rechargeable…”），
  从属关系只能从“according to claim 1”这类措辞解析。

## Decision

### 1. 权利要求树

每项权利要求记录：编号、全文、所引用的权利要求编号、是否独立、来源与解析方式。

| 来源 | 编号与从属关系 | 可信度 |
|---|---|---|
| 美国授权 XML | 专利局标注（`num`、`claim-ref`） | 结构由来源给出 |
| 欧洲 OPS 文本 | 从文本解析（行首编号、“claim N”引用） | 解析所得，标记为 `parsed_from_text` |

**欧洲的语言**：依 EPC 第 70(1) 条，作准文本是程序语言的文本；其他两种语言的权利要求是译文。
模型记录所用语言与程序语言；用译文比对时标记“非作准文本”。实测：OPS 的 claims 与书目响应均未给出程序语言，
因此程序语言记为未知，每个欧洲权利要求集都附“可能是译文”的提示，不做推断。

### 2. 技术特征（要素）

- 初始拆分：美国按 XML 子句（前序部分 + 各子句）；欧洲按文本中的分号、换行与“wherein/characterised in that”等结构。
  每个特征保存其在权利要求全文中的起止位置，可回溯到原文。
- 撰写人的子句结构**不等于**法律意义上的技术特征。初始拆分一律为 `proposed`，须经人工确认、拆分或合并后
  才进入比对；确认操作记录确认人与时间。
- 从属权利要求的特征 = 其所引用权利要求的全部特征 + 自身新增特征。

### 3. 逐项比对与权利要求级结论

每个特征的比对结论由人（或经人复核的辅助工具）给出，取值：

| 取值 | 含义 |
|---|---|
| `literally_present` | 产品中字面出现 |
| `present_by_equivalent` | 产品中以等同方式出现（等同判断由专业人员作出，模型不计算） |
| `absent` | 产品中不存在，也不构成等同 |
| `undetermined` | 证据不足或尚未判断 |

每个结论附产品证据位置与理由。权利要求级结论按全面覆盖原则（all-elements rule）由特征结论推导：

- 任一特征 `absent` → 该权利要求**不落入**；
- 全部特征 `literally_present` → **字面落入**；
- 全部特征为 `literally_present` 或 `present_by_equivalent`，且至少一个为等同 → **仅以等同方式落入**；
- 其余（含任一 `undetermined`）→ **未定**。

**多项从属权利要求**（如“according to claim 1 or 2”“any preceding claim”）所引用的各项是**择一**关系，
不是叠加关系（37 CFR 1.75(c)；EPC 细则 43(4)）：每一种引用选择构成一条独立的从属路径，
各路径的特征集合 = 路径上各权利要求的特征。只要有一条路径落入，该权利要求即落入。
实现时最初把所引用各项的特征合并为一个集合，这会多要求特征、可能把实际落入的权利要求误判为
“不落入”（危险方向），已改正。

路径数量会随链式“any preceding claim”成倍增长（实测 EP-1819002-B1 权利要求 15 有 2,304 条路径）。
结论按权利要求递推精确计算，不枚举路径：自身有特征不具备，或所有上级路径都不落入 → 不落入；
自身特征具备且至少一条上级路径落入 → 落入；其余为未定。该算法在随机测试中与完整路径枚举逐项一致。
路径明细仅用于展示，超过上限时截断并标明，不影响结论。

**人工确认**：只要路径上仍有 `proposed`（未确认）的特征，该路径不得得出“落入”结论
（未经确认的特征划分可能遗漏特征）。

**边界**：推导结果是风险提示，不是法律意见。等同的认定范围、禁止反悔、各法域差异属于规则包内容，
须经持证专业人员审定，不在本模型中预设。

### 4. 本期不包含

数据库表、API、界面、产品技术特征的录入方式、辅助比对（LLM）、规则包。先以纯函数与真实专利测试固定模型。

## Consequences

- 新增 `modules/fto`：美国 XML 解析、欧洲 OPS 解析、权利要求树与特征模型、比对聚合；测试使用
  覆盖集中真实专利的权利要求（公开数据，裁剪为权利要求部分）。
- 欧洲文本解析的准确性用真实专利逐项核对；无法可靠解析的权利要求标记出来，不静默丢弃。
