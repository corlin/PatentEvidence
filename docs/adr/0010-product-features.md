# ADR 0010: 产品技术特征——自由文本录入、规则拆分、人工确认

- Status: Accepted（产品负责人于 2026-10-04 选定：自由文本，拆分成特征后人工确认）
- Date: 2026-10-04

## Context

FTO 比对（ADR 0008）把权利要求的每个特征与“产品”逐项对照，因此需要产品的技术特征。产品负责人决定：
用户用自由文本描述产品，系统拆分为候选特征，由人确认后才用于比对。

## Decision

### 1. 不复用现有 `feature_set_versions`，另建产品特征表

ADR 0004 曾计划复用特征建模模块。核对代码后决定只复用其**流程模式**（草稿 → 确认 → 修订），不复用其表：

- `feature_set_versions` 被比对、报告、检索三个服务按“本案最新已确认特征集”读取，三者都属于已冻结的可专利性流程。
  产品特征若写入同一张表，会被这些流程当作交底书特征读取；避免这一点需要改动冻结代码。
- 该表要求关联解析后的文档（`document_version_id` 非空），且特征类型是可专利性概念（前序/特征部分），与产品描述不符。

### 2. 拆分：确定性规则，不使用大模型

产品描述是客户保密信息，ADR 0005 规定的敏感度分级路由尚未实现，因此拆分**不调用任何大模型**，只用确定性规则：

- 按换行拆分；行首的列表标记（`1.`、`1、`、`(1)`、`（1）`、`一、`、`-`、`•` 等）作为单元边界，不计入特征文本；
- 行内按 `。；;！？` 以及英文句末（`.`/`!`/`?` 后接空白与新句首）拆分；常见缩写（e.g.、i.e.、etc.、Fig.、No.）不视为句末；
  小数（如 `0.5 mm`）不会被拆开；中文逗号不拆分（同一技术特征常含多个分句）；
- 每个候选特征保存其在原文中的起止位置；过长的候选特征（超过 120 个字符）提示人工拆分。

规则拆分只给出候选，**不保证**与技术上的特征划分一致，因此必须经人工确认。

### 3. 存储（机构数据，强制 RLS）

产品描述属于客户的保密数据，与公开专利数据不同：三张表都带 `organization_id`、`case_id`，启用 FORCE RLS（ADR 0006 的全局表模式不适用）。

| 表 | 内容 | 可变性 |
|---|---|---|
| `product_descriptions` | 产品描述全文的每个版本：文本、SHA-256、创建人 | 只追加（运行时角色仅 SELECT/INSERT） |
| `product_feature_sets` | 某版描述的特征集：版本号、状态（`draft`/`confirmed`）、拆分规则版本、确认人与时间 | 草稿可改；确认后不可改、不可删 |
| `product_features` | 特征：编号、文本、原文位置、来源（`split`/`manual`/`edited`）、顺序 | 所属特征集确认后不可增删改 |

“确认后不可改”由数据库触发器强制（沿用 0001 迁移中的触发器模式），不只依赖应用代码：这是 AGENTS.md 要求的“审批后不可变”边界。
修改已确认的特征集只能新建修订版本。

### 4. 本期范围

纯函数拆分器与模型、迁移、服务层（创建描述版本、生成草稿、编辑、拆分、合并、确认、修订）与测试。
API 与界面在下一步。

## Consequences

- 新增 `modules/fto/product.py`（拆分器与模型）、迁移 `0021_product_features`、产品特征服务与测试。
- 测试文本为**合成文本**（明确标注），不使用任何真实客户资料。
