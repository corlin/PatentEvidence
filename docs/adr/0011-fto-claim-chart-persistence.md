# ADR 0011: FTO 逐项比对（Claim Chart）的存储与人工录入

- Status: Accepted（产品负责人于 2026-10-04 决定：比对结论先由人工录入，不做自动建议）
- Date: 2026-10-04

## Context

ADR 0008 定义了比对模型（权利要求特征、逐项结论、全面覆盖原则推导）；ADR 0009 存储了权利要求文本；
ADR 0010 产出了经人工确认的产品技术特征。本 ADR 把三者连起来：一份比对 = 一件专利的权利要求 × 一个已确认的产品特征集，
逐项结论由人录入，权利要求级结论由系统按 ADR 0008 推导。

## Decision

### 1. 一份比对的组成

| 组成 | 来源 | 说明 |
|---|---|---|
| 权利要求快照 | `patent_claim_documents` 中该公开号最新的 `found` 记录 | 创建比对时解析一次并**快照**：权利要求编号、从属关系、特征文本与原文位置、解析器标识、文本 SHA-256、`text_represents`、解析警告 |
| 产品特征集 | `product_feature_sets`（必须为 `confirmed`，且属于同一案件） | 只引用，不复制；已确认的集合本身不可变（ADR 0010） |
| 权利要求特征确认 | 人工 | 按权利要求确认其特征划分；未确认的特征所在路径不会得出“落入”（ADR 0008） |
| 逐项结论 | 人工 | 见第 3 条 |

快照的理由：权利要求文本会被重新获取（新记录），解析器也会改进；比对必须固定在创建时的那份文本与解析结果上，
否则已录入的结论可能对应到不同的特征。

### 2. 存储（机构数据，强制 RLS）

比对结论反映客户产品的分析，属于机构保密数据：

| 表 | 内容 | 可变性 |
|---|---|---|
| `fto_charts` | 案件、公开号、权利要求文档、文本 SHA-256、解析器标识、`text_represents`、权利要求快照（编号、从属、警告）、产品特征集、创建人 | 只追加 |
| `fto_chart_claim_features` | 每个权利要求特征的快照（编号、所属权利要求、文本、原文位置）与确认人、确认时间 | 文本不可改；只允许从未确认变为已确认，确认后不可撤销 |
| `fto_feature_findings` | 每次录入一行：特征编号、结论、对应的产品特征编号、理由、录入人、时间 | 只追加；同一特征以最新一条为准，历次录入保留 |

### 3. 录入规则

结论取值同 ADR 0008：`literally_present`、`present_by_equivalent`、`absent`、`undetermined`。

- `literally_present`、`present_by_equivalent`：必须指明至少一个对应的产品特征编号（结论必须指向产品证据），
  且编号须属于本比对引用的产品特征集。
- `present_by_equivalent`、`absent`：必须填写理由（这两类判断对结论影响最大，须可复核）。
- 是否构成等同由专业人员判断并录入，系统不计算。

### 4. 结论与提示

权利要求级结论在读取时按 ADR 0008 由最新结论推导（精确算法，覆盖多项从属的择一路径），不入库。
每份比对随结果返回不可省略的提示：

- 美国文本为授权时文本（`as_granted`），授权后的复审、IPR、更正可能改变权利要求；
- 欧洲文本可能是译文，作准文本的语言未知（ADR 0008）；
- 结论是风险提示，不是法律意见。

### 5. 审计

写操作经 `access.mutation` 记录审计；审计摘要只含编号与结论取值，不含权利要求或产品文本、不含理由正文。

## Consequences

- 新增迁移 `0022_fto_charts`、比对服务与 API、测试。界面在下一步。
- 权利要求文本须事先已获取（ADR 0009）；未获取时创建比对返回 409，不在请求路径中调用外部接口。
